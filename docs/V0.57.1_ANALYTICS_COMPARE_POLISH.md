# Luxury TimeForge V0.57.1

## Dữ liệu chuyển đổi

Trang khách ghi nhận năm event chính bằng hệ thống first-party:

- `page_view` → PageView
- `product_view` → ViewContent
- `add_to_cart` → AddToCart
- `checkout_started` → InitiateCheckout
- `checkout_completed` → Purchase

Event được giữ giới hạn trên trình duyệt để giao diện không bị chặn và được gửi theo batch tới `/api/analytics/events`. API hợp lệ hóa payload rồi lưu theo ngày tại `timeforge/analyticsEvents/YYYY-MM-DD/{eventId}` khi Firebase server đã cấu hình. Admin đọc Firebase và trộn với event local chưa kịp đồng bộ; nếu Firebase không khả dụng thì chỉ dùng dữ liệu local đúng khoảng ngày đã chọn.

Thanh trạng thái trong Meta Admin hiển thị rõ số event đã đọc từ Firebase và số event chỉ còn trên máy này/chờ đồng bộ, nên Admin không phải đoán nguồn của con số đang xem.

Số liệu này là đo lường first-party của website. Nó không phải số được kéo từ Meta Ads Manager. Dashboard Meta chỉ lọc attribution dựa trên UTM, `fbclid` và referrer; cần đối chiếu Ads Manager khi đánh giá chiến dịch.

`InitiateCheckout` chỉ được ghi một lần khi trang checkout có giỏ hàng hợp lệ. Nút “Mua ngay” ghi `AddToCart` với nguồn `buy_now`, tránh việc một lượt mua bị tính hai lần trước và sau khi đổi route.

## Trang khách

- `/compare` dùng bảng semantic: tiêu chí nằm theo hàng, sản phẩm nằm theo cột và luôn ở cạnh nhau. Tablet/mobile cuộn ngang thay vì chuyển mỗi sản phẩm xuống một hàng.
- Bộ bóc tách thông số ưu tiên cột `rawShopify`/metafield, sau đó HTML rồi description text. Nhãn dài được nhận trước nhãn ngắn để tránh nhầm “Chất liệu vỏ máy” với “Máy”.
- Link so sánh có thể chia sẻ bằng query `products`, và khách có thể thêm vào giỏ ngay trong bảng.
- Watch Finder lập chỉ mục nội dung/thông số một lần theo catalog, hiển thị lý do khớp và cho sửa trực tiếp từng câu trả lời.
- Header, bộ chọn số lượng và các breakpoint tablet/mobile được tinh gọn.

## Admin

- Event Explorer: chọn 7/14/30 ngày, xem tất cả traffic hoặc chỉ Meta, lọc/tìm event và xuất CSV.
- Catalog Health: phát hiện ảnh không công khai, thiếu/trùng SKU, thiếu handle, giá/mô tả không hợp lệ và hết hàng; có CSV lỗi riêng và Meta Catalog CSV.

## Performance

- PageView chỉ phát sinh khi đổi route; thay đổi query trên cùng route chỉ cập nhật attribution.
- Compare state chuyển sang external store nhỏ để cart/catalog update không làm phát tán render qua toàn cây ứng dụng.
- Parser và bộ lập chỉ mục Watch Finder dùng cache; CSS chuyên biệt vẫn route-lazy.
- Store identity Firebase được tải ngay bằng request nhỏ; catalog lớn vẫn giữ chiến lược stale-while-revalidate lúc idle.
- Production report hiện giữ entry chính khoảng 96,3 KiB gzip; Compare/Watch Finder khoảng 6,6 KiB JS + 2,9 KiB CSS gzip và Meta Admin khoảng 7,0 KiB JS + 3,3 KiB CSS gzip, đều tách theo route.
