# Luxury TimeForge V0.57.0

## Kết quả audit và tối ưu

- Ảnh sản phẩm từ Shopify CDN trước đây luôn dùng file gốc. `SmartImage` giờ tạo URL theo chiều rộng, `srcset`, `sizes`, lazy loading và kích thước cố định cho cả Shopify lẫn Cloudinary.
- Lịch sử analytics trên trình duyệt giảm từ 2.500 xuống 600 event, có cache theo chuỗi dữ liệu và không parse lại ở mỗi lần đọc.
- Event gửi về server theo lô tối đa 12 bản ghi, trì hoãn 1,2 giây và dùng `sendBeacon` khi rời trang; hành động mua sắm không chờ request analytics.
- Dữ liệu analytics công khai được giới hạn kích thước, whitelist loại event, rút gọn referrer/metadata và chỉ server mới có quyền ghi Firebase.
- Cấu hình marketing được tách khỏi cấu hình thanh toán. Trang khách chỉ đọc nhánh marketing nhỏ và Meta Pixel không tải khi chưa bật hoặc Pixel ID không hợp lệ.
- Trang Compare, Watch Finder và Meta Ads đều được tách chunk theo route.

### Số đo production

- Entry JavaScript chính: **109,71 KB → 96,15 KB gzip** (**-12,4%**) dù đã bổ sung các tính năng mới.
- CSS tải cùng storefront: **104,25 KiB → 101,83 KiB gzip**; CSS đầy đủ của Compare/Watch Finder chỉ tải khi mở hai route đó.
- Compare + Watch Finder: 3,91 KB JS + 2,41 KB CSS gzip, tải theo route.
- Meta Ads Admin: 5,11 KB JS + 2,33 KB CSS gzip, tải theo route.

## Tính năng Admin cho Meta Ads

- Tổng quan phiên Facebook, thêm giỏ, đơn hoàn tất và doanh thu 7 ngày.
- Bật/tắt Meta Pixel, kiểm tra trạng thái runtime và gửi ViewContent thử nghiệm.
- Theo dõi năm event chuẩn: PageView, ViewContent, AddToCart, InitiateCheckout và Purchase.
- Tạo link quảng cáo có `utm_source`, `utm_medium`, `utm_campaign`, `utm_content` nhất quán.
- Xuất Meta Catalog CSV với ID khớp `content_ids`, giá, tồn kho, link và ảnh sản phẩm.
- Báo cáo phễu theo `utm_campaign`; số liệu website được ghi chú rõ là cần đối chiếu Ads Manager.

## Hai tính năng trang khách

1. **So sánh sản phẩm:** chọn tối đa ba mẫu ngay ở card hoặc trang chi tiết; danh sách giữ trên thiết bị và bảng so sánh chuyển sang dạng card dễ đọc trên mobile.
2. **Tư vấn chọn đồng hồ:** bốn câu hỏi về người đeo, ngân sách, phong cách và thương hiệu; kết quả chấm trực tiếp từ catalog đang xuất bản/còn hàng.

## Cấu hình triển khai

1. Giữ file `.env.local` đang dùng hoặc tạo từ `.env.example`. Không đưa credential server lên biến `VITE_*`.
2. Đặt `FIREBASE_DATABASE_URL` và `FIREBASE_DATABASE_AUTH` ở môi trường server để API đơn hàng và analytics hoạt động.
3. Tạo lại rồi deploy `firebase.rules.json` bằng các script `firebase:rules:generate` và `firebase:rules:deploy`.
4. Vào **Admin → Marketing → Meta Ads**, nhập URL website và Pixel ID, lưu rồi dùng **Gửi event thử** trước khi bật chiến dịch.

## Nợ kỹ thuật còn lại

Storefront cũ vẫn mang nhiều lớp CSS tương thích từ các phiên bản trước (101,83 KiB gzip ở route đầu). Bản này tách CSS mới khỏi tải đầu và không purge tự động các selector động của Theme Editor/Admin để tránh hồi quy giao diện. Nên xử lý tiếp bằng một đợt hợp nhất stylesheet có visual regression riêng, thay vì xóa hàng loạt trong bản đang chạy quảng cáo.
