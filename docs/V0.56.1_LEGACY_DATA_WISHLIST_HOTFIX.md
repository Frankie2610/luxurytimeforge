# V0.56.1 — Legacy data and Wishlist hotfix

## Fixed Admin routes

The product and theme read boundaries now normalize historical Firebase/local records before React renders them.

- Products always receive arrays for images, tags, variants, options and metafields.
- Missing variants receive one safe default variant derived from the old product values.
- Old string or Firebase-map values are converted without discarding usable media, tags or metafields.
- Invalid historical SKUs remain readable in Admin; the existing validation still blocks an invalid key when the merchant explicitly saves it.
- Collections always receive product ID and condition arrays.
- Draft, published and versioned themes always receive all storefront templates with section and block arrays.
- Product Editor, Online Store overview and Theme Editor add local guards as a second safety boundary.

These changes address the route-boundary fallback and the `Cannot read properties of undefined (reading 'filter')` family of failures caused by old resource shapes.

## Wishlist correction

- Removed the padded, nested media-card treatment.
- Product media is now a square, edge-to-edge surface using centered `object-fit: cover` cropping.
- Mobile uses two consistent product columns instead of the previous horizontal card.
- The mobile “Danh sách yêu thích” heading is 26px and becomes 24px on narrow phones.
- Vendor, title, price, stock state and action buttons use a smaller, denser mobile scale.
- Compare and sale controls remain overlaid without changing image dimensions.
- Offscreen cards retain `content-visibility` containment to reduce work during scrolling.
