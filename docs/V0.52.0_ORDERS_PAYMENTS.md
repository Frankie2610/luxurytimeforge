# Luxury Timeforge V0.52.0 — Orders, bank transfer and PayOS

## Fixed order flow

Storefront checkout no longer writes directly to Firebase Realtime Database. All COD, bank-transfer and PayOS orders are created through `POST /api/orders/create`. The server re-reads catalog prices, inventory, discounts and payment settings before writing the order, customer, inventory changes and adjustment history in one multi-path Firebase update.

Admin listens to `timeforge/orders` in realtime. Legacy array-shaped order data is migrated to an object keyed by order ID after an authenticated Admin opens the app.

## Bank transfer

Admin → Settings → Payments & Shipping supports multiple bank accounts, a preferred account, and a bank-transfer discount configured as either percentage or fixed VND amount. The public checkout reads only these non-secret settings. The chosen bank account is snapshotted into each order so later settings changes do not alter old orders.

Admin can manually confirm that a bank transfer was received. The order records `paidAt`, `bankTransferConfirmedAt` and `paymentConfirmationSource`.

## PayOS

PayOS orders are saved before a payment link is created. The PayOS hosted checkout shows the QR code. The webhook or status verification updates the Firebase order to paid automatically.

Server-only Vercel variables:

```env
FIREBASE_DATABASE_URL=
FIREBASE_DATABASE_AUTH=
PUBLIC_SITE_URL=
PAYOS_CLIENT_ID=
PAYOS_API_KEY=
PAYOS_CHECKSUM_KEY=
PAYOS_LINK_TTL_MINUTES=15
```

Do not prefix secret variables with `VITE_`.

Set the PayOS webhook URL to:

```text
https://YOUR_DOMAIN/api/payments/webhook
```

## Firebase Rules

`timeforge/settings/integrations` must be publicly readable because the storefront needs enabled payment methods, bank account details, transfer discount and free-shipping threshold. It remains Admin-write only. `timeforge/orders` remains authenticated Admin-read/write; public order creation uses the server credential.

## Shipping

Admin order detail supports fulfillment, carrier, tracking number, tracking URL, shipment status and delivered status. An optional signed shipping webhook can update these fields using `SHIPPING_WEBHOOK_SECRET`.
